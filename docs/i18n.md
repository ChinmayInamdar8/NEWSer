# Web language translation (English / Marathi)

Daily Corner’s **web** app (`apps/web`) is translated with **[next-intl](https://next-intl.dev)** (App Router). English is the default. Marathi is the second locale. More languages can be added later without changing page files.

The **admin** app is English-only. Nest / Google OAuth have no locale; they do not need translation.

---

## URL rules

English has **no prefix**. Marathi uses **`/mr`**.

| Locale | Home | Login | Future example |
| --- | --- | --- | --- |
| English (`en`, default) | `/` | `/login` | `/posts` |
| Marathi (`mr`) | `/mr` | `/mr/login` | `/mr/posts` |

`/en` redirects to `/` so the default language is never duplicated. Unknown prefixes (e.g. `/fr`) 404.

**The URL is the source of truth.** `/mr` is Marathi; `/` is English. The dropdown only changes language by navigating to those URLs. Middleware does **not** redirect `/` to `/mr` based on cookie or browser language (`localeDetection: false`), so you can always type `/` to get English after viewing `/mr`.

Google OAuth still returns to `WEB_ORIGIN` (`/`), which is English. Use the dropdown if you want Marathi after sign-in.

## How it is wired

```text
Request  →  middleware.ts (next-intl)
         →  app/[locale]/... pages
         →  messages/en.json or messages/mr.json
```

| File | Role |
| --- | --- |
| [`apps/web/i18n/routing.ts`](../apps/web/i18n/routing.ts) | `locales: ['en', 'mr']`, `defaultLocale: 'en'`, `localePrefix: 'as-needed'` |
| [`apps/web/i18n/navigation.ts`](../apps/web/i18n/navigation.ts) | Locale-aware `Link`, `useRouter`, `usePathname`, `redirect` |
| [`apps/web/i18n/request.ts`](../apps/web/i18n/request.ts) | Loads `messages/{locale}.json` for the request |
| [`apps/web/middleware.ts`](../apps/web/middleware.ts) | Detects locale, cookie, and prefixes |
| [`apps/web/next.config.ts`](../apps/web/next.config.ts) | `createNextIntlPlugin('./i18n/request.ts')` |
| [`apps/web/messages/en.json`](../apps/web/messages/en.json) | English copy |
| [`apps/web/messages/mr.json`](../apps/web/messages/mr.json) | Marathi copy |
| [`apps/web/global.d.ts`](../apps/web/global.d.ts) | Types `Messages` from `en.json` |
| [`apps/web/components/language-switcher.tsx`](../apps/web/components/language-switcher.tsx) | EN / मराठी dropdown |
| [`apps/web/app/[locale]/layout.tsx`](../apps/web/app/[locale]/layout.tsx) | `NextIntlClientProvider` |
| [`apps/web/app/layout.tsx`](../apps/web/app/layout.tsx) | `<html lang={locale}>` and Devanagari font for `mr` |

Pages live under `app/[locale]/` (e.g. `page.tsx`, `login/page.tsx`). You never put `en` or `mr` in the folder name.

## Using translations in UI

**Client components** (`"use client"`):

```tsx
import { useTranslations } from "next-intl"

const t = useTranslations("home")
t("tagline")
t("signedInAs", { name: user.email })
```

**Links between pages** must use the i18n `Link`, not `next/link`, so Marathi keeps `/mr`:

```tsx
import { Link } from "@/i18n/navigation"

<Link href="/login">{t("signIn")}</Link>
```

Switching locale without changing the page:

```tsx
import { usePathname, useRouter } from "@/i18n/navigation"

router.replace(pathname, { locale: "mr" })
```

JSON keys are nested. `useTranslations("home")` plus `t("signIn")` reads `home.signIn`. `{name}` in the string is a placeholder passed as the second argument.

Keep **DAILY CORNER** in the heading as product branding when that is intentional; message files may still have `brand.name` for other uses.

## Adding or changing copy

1. Add the same key to **both** `messages/en.json` and `messages/mr.json`.
2. Use `useTranslations("section")` in the component.
3. Typecheck (`pnpm --filter web typecheck`) will fail if a key exists in code/types from `en.json` but you typo the namespace.

Do not hard-code user-visible English in pages except brand text you have agreed to leave untranslated.

---

## Adding a third language (e.g. Hindi)

1. Add the locale code to `routing.locales` in `apps/web/i18n/routing.ts` (e.g. `"hi"`).
2. Add `apps/web/messages/hi.json` with the **same key tree** as `en.json`.
3. Extend `Locale` in `apps/web/global.d.ts` (`"en" | "mr" | "hi"`).
4. Add a label in `common` (and in the language switcher if it special-cases `mr` vs `en` — prefer mapping locale → translation key so new languages do not need extra `if`s).
5. URLs: English stays unprefixed; Hindi would be `/hi`, `/hi/login`, `/hi/posts`.

---

## Sign-in vs translation

Google sign-in lives on **`/login`** (and `/mr/login`). The homepage only links there. Locale-aware `Link` makes that `/mr/login` when the UI is Marathi. The Google button label is `auth.continueWithGoogle`. The OAuth URL itself is not locale-prefixed (it goes to the Nest API).
